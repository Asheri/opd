#    （通过架构裁剪把三套环境合一，详见 DEPLOY.md 第 3 节）。
#    本文件仅在「想保留完整 verl/slime 框架、接受多环境」时使用。
# ============================================================================
# 涵盖论文：
#   AsyncOPD    (arXiv:2606.24143)  -> 流式异步调度器   [opd/]
#   Direct-OPD  (arXiv:2607.05394)  -> verl，改迁移对象  [Direct-OPD/verl]
#   Lightning-OPD(arXiv:2604.13010) -> slime，离线教师缓存 [Lightning-OPD/slime]
#
# 本文件以 AsyncOPD 的 pin 为锚点（torch 2.9.1 / CUDA 12.8），作为「异步调度器」
# 的统一运行时，也是 main/ 全栈 demo 的运行底座。
#
# ⚠️ 为什么不能直接把三个 repo 装进同一个环境？
#   - numpy：AsyncOPD 钉 numpy==2.2.6，而 Direct-OPD(verl) 要求 numpy<2.0.0 —— 硬冲突。
#   - vllm ：AsyncOPD 用 vllm==0.16.0，verl 的 vllm extra 上限 vllm<=0.11.0 —— 冲突。
#   - torch：verl 的 sglang 路径钉 torch==2.8.0，本环境用 2.9.1。
#   => 建议：AsyncOPD 用本环境；Direct-OPD / Lightning-OPD 各自独立虚拟环境
#      （见 requirements-direct-opd.txt / requirements-lightning-opd.txt）。
#      三者仅在「数据 / 离线缓存」层耦合（这正是 main/ demo 抽象掉的部分）。
#
# Python: 3.12（flash-attn 预编译 wheel 为 cp312）
# 安装：  pip install -r requirements.txt
#   若 pip 默认拉到的不是 CUDA12.8 wheel，可改用：
#   pip install torch==2.9.1 --index-url https://download.pytorch.org/whl/cu128
# ============================================================================

> 日期：2026-08-14 ｜ 目标：训练数据从默认/GSM8K 换成论文 Skywork-OR1 math 后，
> 重新训练 Qwen3-1.7B 学生，**保持/超过此前 ms_17b 的健康收敛轨迹**（E[Δ_T] 0.013→0.060
> 单调上升、step120 最优、AIME 短生成 13.3%/16.7%）。
> 约束：单卡 RTX PRO 6000 96GB（服务器恢复后执行）；transformers 原生（非 vLLM）。
>
> **状态注记（2026-08-14 更新）**：L2 Adaptive Teacher Cache 已实现并闭环（四能力 + 双池
> feeder + E0-E6 + resume，233 测试全绿），HFCausalLM 已含 `generate_batch` 骨架。
> 本计划**从纯 L0 升级为「L0 基线 + 可选 L2 半在线周期刷新」**：阶段 2 跑 E0（L0）建立健康
> 收敛基线，阶段 4 跑 E5（全 L2）对照量化贡献。若 L2 刷新相位在真实模型不稳，退 L1 方案 A

## 背景与关键约束（探索结论）

1. **此前 ms_17b 健康收敛超参**（服务器实测，必须复用）：
   `lr=3e-5`、`kl_reg_coef=0.5`、`delta_clip=2.0`、`top_k_teacher/student=256`、
   `renormalize_topk_support=true`、`batch_size=8`、`n_steps=200`（step120 最优、step199 过训）、
   `dtype=bf16`、`cache_mode=topk`、`warmup_M=0`（L0）。
2. **HFCausalLM 已有 `generate_batch` 骨架（L2 实现新增，需 GPU 验证）**：
   model_factory.py 现在含 `HFCausalLM.generate_batch`（调 transformers generate）。
   → **Stage1 的 L1 warmup（student_init）与 L2 刷新相位在 HF 路径下理论上可用**，不再是
   此前"只能用 L0"的硬约束。但生成骨架的 padding/mask 未在真实模型验证，稳妥起见：
   - **base 缓存**仍用外部脚本预生成 response（阶段 0.4，稳）；
   - **L2 on-policy refresh** 由训练期刷新相位在线生成（阶段 4，需先 GPU 验证 `generate_batch`）。
3. **JsonLinesDataLoader 要求 prompt+response 都非空**（data.py 跳过空 response 行）。
   Skywork 原始只有 prompt+ground_truth，**必须预生成 response**（base 缓存前置）。
4. **prepare_skywork_math.py 输出 parquet**（DAPO prompt + gt），JsonLinesDataLoader 读 jsonl
   → 需额外 parquet→jsonl + 子集采样 + response 预生成三步。
5. **教师对**：1.7B 用 JustRL-DeepSeek-1.5B（teacher_rl）/ DeepSeek-R1-Distill-Qwen-1.5B
   （teacher_ref），同 R1/Qwen2.5 家族（已下载，服务器 models/ 目录）。
6. **model_kind=hf 跳过 Stage0 RL**，直接用预下载教师对（pipeline.py _stage0_teachers）。
7. **L2 Adaptive Teacher Cache 已实现并闭环**（本轮工作，见
   `docs/superpowers/reports/2026-08-14-adaptive-teacher-cache-implementation.md`）：
   四能力（Disagreement / Health Monitor / Dynamic Ratio / Selective Rollout）+ **双池 feeder
   闭环（refresh 样本真正进训练）** + E0-E6 矩阵 + resume 精确续跑，233 测试全绿。
   → 本计划可把 L0 静态缓存升级为**可选 L2 半在线周期刷新**（阶段 4），用 E0/E5 对照量化贡献。

## 阶段 4：L2 周期刷新增强（推荐）

> **目的**：把 L0 静态缓存升级为 L2 半在线周期刷新，用 on-policy 样本周期 refresh 教师缓存，
> 进一步缓解曝光偏差（L0–L3 曝光偏差谱上比 L1 更高一级）。L2 四能力 + 双池 feeder 闭环
> 已实现（见 `docs/superpowers/reports/2026-08-14-adaptive-teacher-cache-implementation.md`，
> 233 测试全绿），本阶段是**把 L2 接入 Skywork 重训练**，并跑 E0（L0 基线）vs E5（全 L2）对照。

### 4.1 单卡适配（L2 不依赖双卡）

L2 交替相位是**单进程**（训练相位 ↔ rollout 刷新相位 ↔ refresh 训练相位分时复用同一张卡），
不强制 FSDP 双卡。本计划沿用单卡 RTX PRO 6000 96GB：
- 训练相位：base 池 `_train_step`（teacher-free，一行不动）；
- 刷新相位：`run_refresh_phase` 常驻教师对前向 + student `generate_batch` 生成 on-policy response；
- refresh 训练相位：`_train_step_refresh` 从 ring buffer 取 `s_old + Δ_T` 做稀疏 top-K PG+KL。
- 双卡 FSDP / colocated CPU offload 是**可选多卡变体**（骨架），本计划不启用。

**L2 单卡显存构成**（pipeline 装配实际驻留）：`student` + `student_ref`（初始副本）+
scheduler hf worker（另一份学生副本）+ `teacher_rl` + `teacher_ref` ≈ **3×1.7B + 2×1.5B ≈
8.2B 参数**，bf16 ≈ **16.4GB**，远低于 96GB，无需 offload。与 §2.2 的 L0（载入缓存后仅
student + worker ≈ 3.4B）相比多驻留约 4.8B，单卡可忽略。

**⚠️ 前置（必须先 GPU 验证）**：`HFCausalLM.generate_batch` 是骨架，padding/mask 未在真实模型
验证。刷新相位依赖它，须先跑通 1 条 prompt 的生成（见 §3.3 前的冒烟）。

### 4.2 配置（l2 段参考值，`--set` 注入，不改共享 yaml）

⚠️ **不要把这些 l2 键写进共享 `skywork_17b.yaml`**——阶段 2.2 的 E0（L0）训练用同一 yaml，
写进去会污染基线。正确做法：阶段 4.3 用 `train --set l2.*` 注入（或另存 `skywork_17b_l2.yaml`）。
以下为 E5 完整参考值，已通过本地 `info` 校验（config.py `L2Cfg` schema，`extra="forbid"`）：

```bash
# E5 的 l2 全量覆盖（运行时注入，写进 yaml 的等价物）
--set l2.enabled=true \
--set l2.t_train=100 --set l2.m_refresh=256 \
--set l2.cache.refresh_size=2048 --set l2.cache.max_response_length=8192 \
--set l2.cache.refresh_min_interval=50 --set l2.cache.refresh_max_interval=150 \
--set l2.disagreement.enabled=true --set l2.health_monitor.enabled=true \
--set l2.refresh_ratio.mode=adaptive --set l2.refresh_ratio.initial=0.30 \
--set l2.refresh_ratio.min=0.10 --set l2.refresh_ratio.max=0.60 \
--set l2.selective_rollout.enabled=true --set l2.selective_rollout.candidate_multiplier=4 \
--set l2.selective_rollout.value_fraction=0.80 --set l2.selective_rollout.coverage_fraction=0.20 \
--set l2.selective_rollout.exploration_fraction=0.20 \
--set l2.utility.disagreement_weight=0.5 --set l2.utility.reward_weight=0.3 \
--set l2.utility.age_penalty=0.2
```

> 语义注：
> - `t_train=100` + `n_steps=200` → 2 个相位边界，G4（`refresh_min/max_interval`）下各触发
>   一轮刷新，共 2 轮（冷启动首相位必刷）。
> - l2 的 refresh 训练步是**补充步**，E5 总步数会 >200（不计入 base n_steps 口径）。
> - `disagreement.enabled` / `health_monitor.enabled` 目前是**纯配置开关**：pipeline 恒构造
>   `DisagreementComputer` / `CacheHealthMonitor`（实现报告 §8 已知问题 3），enabled 不 gating
>   计算，仅作 E0-E6 的语义标记。真正 gate 刷新的是 `selective_rollout.enabled`（selector 为
>   None 时刷新相位整体短路，见 4.5 已知问题）。

### 4.3 运行（E0 基线 vs E5 全 L2 对照）

```bash
  --set l2.selective_rollout.coverage_fraction=0.20 --set l2.selective_rollout.exploration_fraction=0.20
```

> E0/E5 共用同一 `cache_skywork_17b.pt`（load_cache=true）：base 池相同，只有 L2 是否注入不同，
> 对照干净。E0 复跑可复用阶段 2.2 结果（同命令同 run-dir）。

### 4.4 判据（不只盯 final benchmark）

- **训练质量**：E5 的 E[Δ_T]（`metrics` 的 `adv_mean`）单调上升轨迹应 ≥ E0（L2 不劣于 L0），
  AIME ≥ 或≈ E0。
- **效率比值（L2 价值核心）**：`Performance/Teacher Compute =` 有效 Δ_T 信号 token / 教师前向
  token，`Performance/Rollout Tokens =` 有效训练推进 / rollout 生成 token。
  ⚠️ **当前未实现**（实现报告 §9.5：rollout 相位未显式统计 `teacher_forward_tokens` /
  `rollout_tokens`，现用 `total_s` 作代理）。若要用这两大比值下结论，需先加成本核算模块
  （stat 注入 metrics），否则退而用 `timings.json` 的 `total_s` 对比 E0/E5。
- **判定**：若 E5 用更少教师前向（或相近 total_s）达到 ≥ E0 的 AIME → L2 确立价值，取 E5 为
  最终学生；若 E5 仅略低于 E0 但效率大幅提升 → 记录 trade-off，仍可选 E5 或退 E0。

### 4.5 已知问题（E6 语义缺陷，勿用 E6 下 selective 结论）

`pipeline.py` L2 循环的刷新触发条件是 `elapsed >= refresh_min ... and selector is not None`
（`_run_body`）。因此 **`selective_rollout.enabled=false`（E6）时 selector=None，刷新相位整体
被短路**——E6 实际退化为纯 base 训练，**不是「random rollout」**。若用 E6 论证"random rollout
劣于 selective"，结论不成立（实现报告 §7 的 E6 数字即此退化产物）。本计划只跑 E0/E5，不受影响；
若后续要测 random rollout 对照，需先修该触发条件（refresh 相位不应依赖 selector 存在，仅
选择策略退化为 uniform）。

## 可选增强①：L1 warmup（离线多 response，备用）

若 L2 的 `generate_batch` 骨架 GPU 验证不过，或无多余 compute 跑刷新，退回离线 L1：
- **方案 A（推荐，零代码改动）**：阶段 0.4 预生成时每条 prompt 生成 **M+1 条 response**（M=4），
  拼成 10K×5=50K 条胖 D jsonl，Stage1 直接读（warmup_M=0 但数据已含多样 response）。
  相当于"离线 L1"。
- **方案 B**：验证 `HFCausalLM.generate_batch` 后，`warmup_source=student_init` 走训练期 warmup。

建议顺序：**先跑 E0（L0）→ 再跑 E5（L2）→ 若 L2 刷新相位不稳则退 L1 方案 A**。

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| Skywork response 预生成耗时长 | 逐题落盘 + resume（复用 eval_aime progressive）；flash_attn 加速 |
| 初始 student response 质量差（1.7B 未训练） | on-policy 对齐论文；Δ_T 信号来自教师对（与 response 质量弱相关） |
| 过训（step199 跌落） | checkpoint_every=20 + step100/120/140 评估 + 早停 |
| Δ_T 爆炸（Skywork 真实词表） | delta_clip=2.0 + top_k=256 稀疏 |
| 显存（10K 条 cache） | topk 缓存 ↓1000× + offload_to_cpu |
| 单卡训练+评估不能并行 | 训练完再评估（串行） |
| **L2 `generate_batch` 骨架未 GPU 验证** | 阶段 4.1 前置冒烟（1 条 prompt）；不稳则退 L1 方案 A |
| **L2 刷新相位耗教师 compute** | `m_refresh` 远小于 base（256<<10K）+ `refresh_max_interval` 门控；E0/E5 对照量化贡献 |
| **单卡 L2 交替相位显存（teacher 常驻 + student）** | 96GB 充裕（3×1.7B+2×1.5B≈16.4GB）；必要时 hf 教师 `offload_to_cpu` |
| **checkpoint→HF 导出脚本（`export_checkpoint_hf.py`）未写** | 阶段 1 待办新增；否则阶段 3.1 无法评学生 checkpoint（eval-aime 不吃裸 `.pt`） |

## 验收标准

1. **数据**：skywork_10k.jsonl 10K 条，prompt/response/ground_truth 非空，token 化合规
2. **训练**：200 步跑完，E[Δ_T] 单调上升至 +0.04~0.06，loss 无爆炸
3. **收敛**：step120 附近 AIME ≥ 此前 13.3%/16.7%（短生成），或长生成 ave@8 有提升
4. **对比**：post（训练后）> pre（基座）AIME 分数
5. **L2 对照（阶段 4）**：E5（全 L2）AIME ≥或≈ E0，且 `Performance/Teacher Compute` 显著更优；
   若 L2 刷新不稳，明确记录并退回 E0/L1
6. **文档**：结果填入 TECHNICAL_REPORT.md §5.3 待补表

# Stage 1.5 K 校准 + 生成吞吐校准决策报告

> 状态：**已完成服务器实测（卡1 并行，真实 teacher，~559 条真实 Skywork response）**。
> 脚本：`scripts/k_calibration.py`；数据：`skywork_calib_1000.jsonl`（1000 条真实 Skywork
> prompt + 初始 Qwen3-1.7B 生成的 on-policy response）。

## 1. 目的

在真实 teacher 上给「K 取多少」提供数据依据，替代『凭显存压力降到 16』的拍脑袋。
对每个 response 位置取 teacher_rl 的 full-vocab 分布，比较 K-truncated 稀疏 Δ_T 相对
K=256 参考的保真度：

| 指标 | 定义 | 含义 |
|------|------|------|
| M_K | Σ_{i∈TopK(rl)} p_i | teacher_rl 分布在 top-K 上覆盖的概率质量 |
| C_K | P( y_t ∈ TopK(rl) ) | 真实 chosen token 落在 teacher top-K 内的概率 |
| ρ_K | Corr( Δ_T^(K), Δ_T^(256) ) | K 截断 Δ 与 256 参考 Δ 的 Pearson 相关（256 支撑 pooled） |
| MAE_K | E[ \|Δ_T^(K) − Δ_T^(256)\| ] | 同一支撑上的平均绝对误差（whole-support 口径） |

**决策判据**（用户给定）：若 ρ_64≈1 且 MAE_64 小且 C_64 高 → **K=64 有据可依**，
优于『显存压力降到 16』。

## 2. 数据与口径

- **数据**：Skywork-OR1-RL-Data math parquet（105,055 行）→ 取 1000 条 prompt →
  初始 Qwen3-1.7B 生成 response（temperature=1.0, top_p=0.95, max_new_tokens=1024）。
- **teacher 对**：JustRL-DeepSeek-1.5B（rl，V=151936）vs DeepSeek-R1-Distill-Qwen-1.5B（ref），
  同 DeepSeek 词表。
- **Δ_T(v) = log p_rl(v) − log p_ref(v)**，只在 teacher top-K(rl) 支撑上有值，其余 = 0
  （与 cache 存储语义一致）。Δ_T^(K) 保留前 K 个 delta，K..255 置 0。
- **ρ_K / MAE_K** 在 **256 支撑**上 pooled（只统计 S_256 内元素，避免 V 上万全 0/0 稀释）。
- 参考基准 = K=256（自洽：ρ=1, MAE=0）。

## 3. 实测结果（服务器，卡1 并行，~559 条样本 × 1024 位置 = 572,690 位置）

**执行命令**（见 §5）。数据：真实 Skywork prompt + 初始 Qwen3-1.7B on-policy response，
teacher 对 JustRL-DeepSeek-1.5B / DeepSeek-R1-Distill-Qwen-1.5B（V=151936）。

| K | M_K | C_K | ρ_K_vs_256 | MAE_K_vs_256 | MAE_tail_avg |
|---|---|---|---|---|---|
| 32 | 0.997046 | 0.991465 | **0.321311** | 1.446933 | 1.653637 |
| 64 | 0.998234 | 0.994791 | **0.451112** | 1.241699 | 1.655599 |
| 128 | 0.998790 | 0.996509 | **0.650038** | 0.828150 | 1.656301 |
| 256 | 0.999103 | 0.997500 | 1.000000 | 0.000000 | 0.000000 |

**生成吞吐校准**（teacher_rl，batch=4）：**323.3 tok/s**（gen_tokens=256, wall=3.17s）。

> 注：response 全部正好 1024 token（被 max-new-tokens=1024 硬截断，非 EOS 自然终止），
> 即 Skywork math 的长 CoT 前缀。生成日志『E[L]=128』是进度显示口径（每批 8 行拆算），
> 实际每条就是 1024 token。校准在 1024 长前缀上测 K 保真度，对 8192 训练 bound 是
> 合理的短程采样。

## 4. 结论与推荐（已实测）

**用户决策判据：ρ_64≈1 且 MAE_64 小且 C_64 高 → K=64 有据。实测：ρ_64=0.45，判据不满足。**

关键事实（两个指标阵营分歧，必须并读）：

- **M_K / C_K（分布集中度）极高**：K=32 就覆盖 99.7% 概率质量、99.15% chosen token；
  K=64 → 99.8% / 99.5%。teacher 分布高度集中在 top-32。
- **ρ_K / MAE_K（Δ 向量保真度）偏低**：ρ_64=0.45、ρ_128=0.65，直到 K=256 才到 1；
  MAE_64=1.24（log-ratio 单位，非小）。

**为什么分歧**：概率质量集中在 top-K，但 Δ_T=log p_rl−log p_ref 的**量值在 256 支撑上
铺开**——低概率 token 的 log-ratio 可以很大。所以把缓存截断到 top-K、tail 置 0，会丢掉
真实量级的 Δ（被丢 token 平均 |Δ|≈1.24~1.66）。

**诚实结论**：『凭显存压力降到 16』被彻底否决（ρ_16 只会更低，~0.2）；但 **K=64 也不该
作为保真度档**——ρ_64 远不到 1。由于 S1-7 磁盘 mmap 已消除显存墙（K=128=0.4TB/23min写、
K=256=0.8TB/46min写，均可行），**校准支持的档位是越高越好**：K=128（ρ=0.65）或 K=256
（ρ=1）。训练热路径（delta_for_student_topk 只查 student chosen token）在 K=64 已 cover
99.5%，但缓存是**离线静态**的，student 后续分布未知，ρ 的保守口径更稳。

**三档对照（最终推荐倾向）**：

| 档位 | 盘体(50K×8192) | 写盘 | ρ_64意义 | 推荐 |
|---|---|---|---|---|
| K=32 | 0.1TB | ~6min | 99.7% mass / 99.15% token，ρ=0.32 | 显存最省，保真度低 |
| K=128 | 0.4TB | ~23min | ρ=0.65，99.85% mass | 折中 |
| K=256 | 0.8TB | ~46min | **ρ=1，完整 Δ 保真** | **推荐（盘体可承受）** |

> 若后续要兼顾盘体与保真度且能接受 ρ≈0.65，K=128 是次优。若要『完整 Δ 向量』，K=256。
> 具体取哪档由用户拍板——本报告只提供数据：**ρ/MAE 不支持降档到 64；盘体上 256 可行。**
> 建议下一步：把 `configs/skywork_17b.yaml` 的 `cache.top_k` 从 32 提到 128 或 256，
> 用 S1-7 的 disk 路径 build，代价是写盘 23~46min（一次性的）。

## 5. 执行命令（服务器）

```bash
# 1. 生成 1000 条真实 response（已跑，resume-safe）
/root/miniconda3/bin/python scripts/prepare_skywork_responses.py \
  --jsonl /root/autodl-tmp/datasets/skywork_calib_1000.jsonl \
  --model /root/autodl-tmp/models/Qwen__Qwen3-1.7B \
  --device cuda:0 --batch-size 8 --max-new-tokens 1024 --temperature 1.0

# 2. K 校准
/root/miniconda3/bin/python scripts/k_calibration.py \
  --jsonl /root/autodl-tmp/datasets/skywork_calib_1000.jsonl \
  --teacher-rl /root/autodl-tmp/models/JustRL-DeepSeek-1.5B \
  --teacher-ref /root/autodl-tmp/models/DeepSeek-R1-Distill-Qwen-1.5B \
  --device cuda:0 --batch-size 4 --max-len 1024 --gen-tokens 256 \
  --out /root/autodl-tmp/eval/k_calibration.json
```

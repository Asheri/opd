# ----------------------------------------------------------------------------
# 一套环境跑完整条流水线：
#   小模型 RL → Lightning 离线缓存教师对 Δ_T → AsyncOPD 调度器上的 Direct-OPD 训练
#
# 统一思路（四处架构裁剪，而非硬凑版本）：
#   ① 推理引擎统一为 vLLM 0.16.0
#      - AsyncOPD 的 rollout 本来就用 vllm；
#      - Lightning-OPD 的离线 logprob 预计算（phase2/curation）本来就用 vllm；
#      - sglang 只在 slime 训练器里用 —— 全栈架构里训练器由 AsyncOPD 承担，
#        因此 sglang（及其 torch==2.8.0 钉死）整体裁掉。
#   ② Direct-OPD 不装 verl，vendor 其核心两个纯 torch 函数
#      - _compute_delta_opd_rm_scores / compute_token_reward_direct_advantage
#        都是纯张量运算（本 demo main/fullstack_opd/direct_opd.py 即对应实现）；
#      - verl 的 numpy<2.0.0 / vllm<=0.11.0 / tensordict 钉死随之消失。
#      - 若坚持装完整 verl：pip install -e ./Direct-OPD/verl --no-deps 后手动
#        核对 numpy2 兼容性（备选方案，见 DEPLOY.md 附录）。
#   ③ 训练后端统一为 megatron-core 0.16.1（AsyncOPD 基座）
#      - slime 训练器所需的 megatron-bridge / sglang / modelopt 裁掉；
#      - Lightning 只保留「离线缓存产物」—— 生成它只需 vllm+transformers+
#        pandas+pyarrow（即其 curation 环境，与本环境天然兼容）。
#   ④ SFT 用 async-opd 自带流水线（其 pyproject 明确含 SFT），llamafactory 裁掉。
#
# 锚点：async-opd/requirements.txt 的 freeze 已验证以下组合共存。
# Python 3.12 | CUDA 12.8（驱动 ≥ R570）| 8×H100（demo 不需要 GPU）
#
# 安装：pip install -r requirements-unified.txt
# ============================================================================
